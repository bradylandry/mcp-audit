## Medium

### False positive: `asyncio.run()` and `mcp.run()` classified as subprocess calls
- **File**: `audit/ast_scan.py:375`
- **Issue**: The subprocess detection heuristic includes a suffix-match fallback:
  ```python
  any(name.endswith("." + sp.split(".")[-1]) for sp in _SUBPROCESS_FUNCS if sp.startswith("subprocess"))
  ```
  This extracts the bare name from each `subprocess.*` function (`.run`, `.call`, `.check_call`, `.Popen`, etc.) and flags ANY dotted call ending in that suffix. As a result:
  - `asyncio.run(main())` → ends with `.run` → incorrectly flagged as a subprocess call
  - `mcp.run()` (FastMCP server start) → same
  - Any `obj.call(...)` method → similarly caught
  
  This means running mcp-audit on any FastMCP-based server (including all servers in the `mcp` repo) would produce spurious high/medium subprocess findings, undermining the tool's trustworthiness.
- **Fix**: Scope the heuristic by also checking the receiver name, similar to the HTTP-client disambiguation in `_is_http_client_call`:
  ```python
  subprocess_signals = ("subprocess", "proc", "shell", "cmd", "popen")
  any(
      name.endswith("." + sp.split(".")[-1])
      and any(sig in name.split(".")[0].lower() for sig in subprocess_signals)
      for sp in _SUBPROCESS_FUNCS if sp.startswith("subprocess")
  )
  ```
  Or, more conservatively, drop the suffix-match fallback entirely — the exact catalog `_SUBPROCESS_FUNCS` already includes all standard library subprocess variants, and the suffix fallback was adding false positives without meaningful true-positive coverage.

### Zero-width-unicode severity ternary always evaluates to "high"
- **File**: `audit/findings.py:338`
- **Issue**: 
  ```python
  sev: Severity = "high" if bidi_count > 0 else "high"
  deduct = 3 if bidi_count > 0 else 2
  ```
  The comment above this block distinguishes bidi-override chars (CVE-2021-42574 vector, more dangerous) from plain zero-width chars (hidden-content risk, lower severity). The `deduct` correctly differentiates (3 vs 2), but `sev` is `"high"` in both branches — a copy-paste error where the else branch should be `"medium"` (or whichever tier plain ZWSP warrants). The consequence: a package with a single ordinary zero-width space in a string literal gets the same `high` severity label as one using bidi overrides, and CI scripts using `--max-severity medium` would unexpectedly fail on minor ZWSP findings that the tool author intended to classify lower.
- **Fix**:
  ```python
  sev: Severity = "high" if bidi_count > 0 else "medium"
  deduct = 3 if bidi_count > 0 else 2
  ```
  Add a test that verifies a plain ZWSP-only finding has severity `"medium"` and a bidi-override finding has severity `"high"`.

### Python 3.10 silently skips dependency parsing, returns misleading `dep_source`
- **File**: `audit/ast_scan.py:579`
- **Issue**: On Python 3.10, the `pyproject.toml` branch falls through to:
  ```python
  return [], "pyproject.toml (3.11+ required for full parse)"
  ```
  This returns an empty `dependencies` list, which suppresses the loose-pin check entirely, and puts a human-readable error message in `dep_source` — a field that everywhere else holds a filename. Programmatic consumers parsing `--json-report` and inspecting `scan_summary.dep_source` receive a string that looks like a path but contains diagnostic prose; a simple `Path(dep_source).name` would give garbage. Python 3.10 is still in active use (EOL Oct 2026) and within the `requires-python = ">=3.10"` constraint.
- **Fix**: Return a structured result that separates the error condition from the filename:
  ```python
  return [], "pyproject.toml"   # dep_source stays a filename
  # And add a separate warning in the scan result or raise a specific exception
  # that cli.py can catch and emit a human-readable warning to stderr
  ```
  Alternatively, add `tomli` as a conditional dep (`tomli ; python_version < "3.11"`) and use it as the 3.10 fallback — but that adds a runtime dep to a tool that deliberately avoids them. The cleaner path is to set `requires-python = ">=3.11"` if 3.10 support isn't actually tested.
