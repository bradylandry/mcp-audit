## Medium

### `findings.py`: zero-width unicode severity ternary is dead code — always "high"

- **File**: `audit/findings.py:1284`
- **Issue**: `sev: Severity = "high" if bidi_count > 0 else "high"` — both branches of the ternary assign `"high"`. The comment above says "Bidi-override chars are higher severity" and the deduction does differ (3 vs 2), but the severity label is identical in both branches. This means zero-width-space findings (intended `"medium"`) and bidi-override findings (intended `"high"`) are both reported as `"high"`, misleading reviewers and consumers who gate on severity level via `--max-severity medium`.
- **Fix**: Change to `sev: Severity = "high" if bidi_count > 0 else "medium"` to restore the intended two-tier severity distinction.

## Low

### `ast_scan.py`: subprocess suffix-match heuristic has false-positive surface

- **File**: `audit/ast_scan.py:376`
- **Issue**: The subprocess check includes:
  ```python
  any(name.endswith("." + sp.split(".")[-1]) for sp in _SUBPROCESS_FUNCS if sp.startswith("subprocess"))
  ```
  This fires on any name ending in `.run`, `.call`, `.check_call`, etc. — including framework methods like `asyncio.loop.run`, `app.call()`, `runner.run()`. The primary `name in _SUBPROCESS_FUNCS` check handles the catalog correctly; the suffix fallback adds false-positive risk for common method names.
- **Fix**: Remove the suffix-heuristic fallback, or tighten it to require the receiver name to contain `subprocess` or `proc` as well. The catalog already handles the well-known forms; the heuristic is unnecessary.

### `cli.py`: `--max-severity` combined with `--ascii` flag mentioned in docstring but flag not implemented

- **File**: `audit/cli.py:731`
- **Issue**: The module docstring lists `--ascii` as a valid flag (`mcp-audit /path/to/package --ascii`) but the `argparse` parser defines no `--ascii` argument. Calling `mcp-audit /path --ascii` will exit with an argparse error, which is confusing to users.
- **Fix**: Either add `parser.add_argument("--ascii", action="store_true", ...)` (with logic to strip emoji from the report renderer) or remove `--ascii` from the docstring.
