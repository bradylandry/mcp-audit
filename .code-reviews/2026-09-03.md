## Medium

### Dead branch in severity assignment for zero-width unicode
- **File**: `audit/findings.py:338`
- **Issue**: `sev: Severity = "high" if bidi_count > 0 else "high"` — both branches of the ternary evaluate to `"high"`. The intent (from the preceding comment) was to assign a different severity for bidi-override characters vs. plain zero-width characters. The variable `sev` is then used in the `Finding` constructor but both paths produce identical output. The deduction IS differentiated (`3 if bidi_count > 0 else 2`), so scoring behavior is correct — but the severity label doesn't distinguish the two cases as originally intended.
- **Fix**: Change the non-bidi branch to `"medium"` if that was the original intent, or leave both as `"high"` and remove the dead conditional:
  ```python
  # If both should stay high:
  sev: Severity = "high"
  deduct = 3 if bidi_count > 0 else 2
  ```
  Decide which behavior is correct and add a test that asserts the expected severity for each case.

### HTTP heuristic false-positives on non-HTTP receivers
- **File**: `audit/ast_scan.py:526`
- **Issue**: `_is_http_client_call` uses a receiver name heuristic: any method call ending in a HTTP verb (`get`, `post`, etc.) where the receiver name contains `"client"`, `"session"`, etc. is classified as an HTTP call. This produces false positives for:
  - `redis_client.get(key)` — "client" matches the signal list
  - `self.client_config.get("host")` — "client" appears in "client_config"
  - `self.grpc_session.get(...)` — "session" matches
  
  These would be reported as HTTP calls with URL-construction warnings, inflating findings and reducing the score of packages that use Redis, gRPC, or config dicts.
- **Fix**: Tighten the receiver signal list to exact tokens rather than substring matches. Use `any(sig == part for part in receiver_chain.split("_"))` (word-boundary matching on snake-case names) rather than `any(sig in receiver_chain ...)`. Add a test case with `redis_client.get(...)` to lock in the correct behavior.

### Python 3.10 silently returns empty dependency list
- **File**: `audit/ast_scan.py:578`
- **Issue**: On Python 3.10, `tomllib` is not available (it was added in 3.11). The code catches this with a comment and returns `([], "pyproject.toml (3.11+ required for full parse)")`. However, `pyproject.toml` is one of the primary sources of dependency information, and silently returning no deps means the `MCP011` (loose pins) check never fires on Python 3.10. The project declares `requires-python = ">=3.10"`, so this is a supported configuration.
- **Fix**: Either drop 3.10 support (simplest), install `tomli` as a conditional dependency on 3.10 (`tomli; python_version < "3.11"`), or use the minimal TOML parsing approach with `re` for just the `project.dependencies` key. At minimum, emit a warning to stderr so users on 3.10 know dependency checking is degraded.

### `utf-8 errors='replace'` can suppress detection of malicious strings
- **File**: `audit/ast_scan.py:668`
- **Issue**: Files are read with `errors="replace"`, silently substituting `?` for invalid UTF-8 bytes. Dimension 9 (string-content safety) scans for zero-width and bidi-override characters. A sophisticated attacker could embed a malicious string using non-UTF-8 encoding that is replaced by innocuous `?` characters before the scanner sees it, evading detection. For an audit tool, silent data substitution is especially problematic.
- **Fix**: Use `errors="strict"` and catch `UnicodeDecodeError` explicitly, logging a warning that a file was skipped due to encoding issues. This makes the behavior visible (`"skipped: encoding error"`) rather than silently corrupting the file content before analysis.

### `_guess_package_name` returns directory name for directories
- **File**: `audit/report.py:147`
- **Issue**: `_guess_package_name` returns `Path(r.scan.target_path).name`, which for a directory audit returns the directory name (e.g., `jarvis-trading-mcp`). For single-file audits it returns the filename without extension. When users run `mcp-audit .` the report header reads `Security Audit: .`, which is misleading. When `target_path` is a resolved absolute path (it is, via `Path.resolve()`), `.name` works correctly — but for paths ending in `/` the name could be empty.
- **Fix**: Add a guard: `return p.name or p.parent.name or "package"`. Also consider reading the `name` field from `pyproject.toml` if it was parsed, for a more accurate package name in the report header.
